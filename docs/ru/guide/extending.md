# Расширение редактора

Во Vue-интеграции `PageEditor` принимает документ через `v-model`, а также
настройки блоков, функций, хранилища, темы, языка и плагинов.

```vue
<PageEditor
  v-model="document"
  :locale="locale"
  :messages="messages"
  :plugins="plugins"
  @save="persist"
/>
```

## Свойства и функции

Основные props: `blocks`, `features`, `storage`, `readonly`, `locale`,
`messages`, `uiTheme`, `styleTokens`, `plugins`, `schema` и `dataContext`.
Флаги `features` включают или выключают autosave, history, hotkeys и preview.
Для многостраничного режима используйте `v-model:pages`, `globals` и
`activePageId`.

## Пользовательские блоки

Опишите блок через registry: его тип, отображаемое имя, Vue-компонент рендера,
компонент настроек, начальное содержимое и схему props. Проверяйте входные props
схемой, чтобы документы из хранилища не передавали компоненту некорректные
данные. Для подписей, placeholder и категорий используйте ключи локализации —
тогда они переводятся вместе с интерфейсом.

## Плагины

Плагин добавляет блоки, панели, кнопки, стили и каталоги сообщений. Передайте
его через prop `plugins` во Vue или URL модуля через `plugins`/`loadPlugins` в
embed-клиенте. Сообщения плагинов объединяются по locale; переводы приложения
имеют приоритет.

В комплекте есть плагины AI и CSS Anchor. AI-плагин добавляет настройки
провайдера и генерацию блоков, CSS Anchor — controls для anchor positioning.
Подключайте только те плагины, которые нужны продукту.

## Блоки для других фреймворков и хранилище

Host может быть React, Svelte или обычным HTML через iframe-клиент; сами
пользовательские блоки редактора пишутся на Vue. Передавайте события и JSON
`PageDocument` через API клиента, а результат рендерьте core-пайплайном в любом
фреймворке.

`storage` во Vue отвечает за сохранение и восстановление документа. Реализуйте
его поверх своего API, CMS или local storage; редактор не навязывает бэкенд.
